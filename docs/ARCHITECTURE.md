# Архитектура Textory

Textory построен как один Android-модуль на Kotlin и Jetpack Compose. `TextoryApp` переключает три назначения — домашний экран, открытый документ и viewer версий — обычным сохраняемым состоянием и `BackHandler`; навигационный фреймворк для такого графа не нужен. Домашний экран владеет созданием, импортом и входом в архив, а верхняя панель документа вызывает только сохранение и экспорт. Данные по-прежнему принадлежат одному `EditorViewModel`, а база данных и внедрение зависимостей здесь не дают полезной сложности.

Открытый документ имеет два представления одного `currentText`. `MarkdownPreview` линейно разбирает блоки, удаляет служебные маркеры и отдаёт все блоки в один `Column + verticalScroll` внутри `SelectionContainer`. Lazy virtualization намеренно не используется: Android selection registry одновременно содержит весь документ, поэтому Select all не ограничивается активным viewport. Каждый блок имеет `BringIntoViewRequester`, сохраняющий переходы по diff без lazy index. `RichTextClipboard` сопоставляет выбранный plain fragment с display offsets общего `AnnotatedString` и заменяет clipboard entry на dual-MIME `text/plain + text/html`. HTML сохраняет bold, italic, monospace code, links, размер и block emphasis; если диапазон не найден однозначно, plain остаётся безопасным HTML fallback. Массив raw offsets разбивается на отдельные display runs: скрытые backticks, link destinations и list markers не могут склеить несвязанные области. Один и тот же `textHighlightRects` строит зелёную геометрию и hit-area, поэтому клэмпинг `TextLayoutResult.getOffsetForPosition` за пределами глифов не создаёт ложный тап. Внутри rect действует строгий half-open диапазон `[start,end)` без допуска `±1`; при overlap выбирается наиболее узкий видимый диапазон. First tap, second tap и midpoint голосуют, comparison открывается только при двух совпадениях из трёх.

Inline code использует `FontFamily.Monospace` и зелёный foreground без `SpanStyle.background` в обоих режимах. Selection highlight рисуется непрерывно поверх всего диапазона; opaque span background запрещён, потому что скрывает системное выделение, хотя offset фактически выбран.

`observeTapWithoutConsuming` наблюдает короткий неподвижный tap на initial pointer pass и не consume-ит событие. В read-mode он открывает painted diff одним нажатием; movement больше touch slop и long press отбрасываются, поэтому scroll и системное выделение `SelectionContainer` сохраняются. `observeDoubleTapWithoutConsuming` остаётся дополнительным shortcut с окном 550 мс.

В режиме правки single tap по-прежнему принадлежит `BasicTextField` и ставит cursor. `ChangeHitResolver` сопоставляет cursor/selection с текущим diff; когда совпадение есть, над formatting toolbar появляется компактная круглая кнопка `↔` с touch-area 48 dp. Только эта кнопка открывает историю. На edit-mode `BasicTextField` нет passive pointer observer: double tap полностью принадлежит нативному выделению слова и не может открыть comparison dock. State-based `BasicTextField(TextFieldState)` публикует свежий нативный `TextRange` через `snapshotFlow`; `EditorStateEchoTracker` распознаёт возвращённые родителем snapshots и не позволяет устаревшему echo перезаписать более свежий быстрый ввод. Selection выбирает diff с наибольшей долей пересечения. Любое изменение текста закрывает устаревшее сравнение.

`ComparisonDock` — обычный дочерний overlay корневого `Box`, а не `ModalBottomSheet`: он не создаёт scrim, focus trap или полноэкранный pointer layer. В read-mode dock расположен над navigation bar, в edit-mode — над formatting toolbar и IME. Pure-функция `comparisonDockLayout` выбирает три режима: replacement показывает current/previous рядом; addition помечается `N из M · добавлено` и показывает только full-width current; deletion помечается `· удалено` и показывает только full-width previous. Отдельная карточка отсутствующей версии не создаётся. Каждое непустое тело имеет vertical scroll до 120 dp и использует выбранный editor font size с line height `fontSize × 1.45`; compact-row получает vertical padding 5 dp. Заголовок содержит 48 dp touch-targets previous/next/close; navigation отделена от close промежутком 10 dp, divider 1 dp и ещё 10 dp, поэтому hit-зоны не пересекаются. Высота dock измеряется через `onSizeChanged` и уменьшает как read viewport, так и editor viewport.

Верхний статус показывает `Есть изменения · N` и открывает первый либо текущий diff. `ChangeNavigationRequest` содержит source offset и монотонный token. В read-mode per-block `BringIntoViewRequester` приводит соответствующий Markdown block; в edit-mode selection переносится к offset, а hoisted `ScrollState` показывает change. Pointer input принадлежит только dock, поэтому документ, tabs и toolbar за его пределами остаются интерактивными. Dock закрывается крестиком, Back или vertical drag заголовка вниз на 72 dp; при активной IME первый Back скрывает keyboard, следующий закрывает dock.

Подсветка реализована по-разному из-за scroll geometry. `MarkdownPreview` не имеет внутреннего text scroll, поэтому рисует округлённые прямоугольники по `TextLayoutResult`. State-based editor применяет syntax и diff-стили через `OutputTransformation.addStyle`, не вставляя и не удаляя символы. Экземпляр transformation стабилен на протяжении edit-session и читает актуальные highlight ranges, поэтому обновление diff не перезапускает IME connection. Фон становится частью отображаемого текста, прокручивается вместе с глифами и одинаково работает для Unicode/Latin/Markdown; identity source offsets сохраняются для cursor и hit-testing. Нулевые deletion-ranges в редакторе не рисуются; корректный боковой маркер остаётся в read-only блоках.

Глобальный `EditorAppearancePreferences` хранит общий размер текста обоих режимов в `SharedPreferences`, а `EditorViewModel` публикует его отдельным `StateFlow`. Размер меняется с шагом 1 sp без верхнего лимита; единственная нижняя граница — технически валидный 1 sp. Non-finite сохранённое значение восстанавливается к 17 sp. В edit-mode масштабируются body, line height и syntax headings; в read-mode — body, Markdown hierarchy, quotes, lists и code, включая historical viewer. Настройка отображения не входит в `EditorUiState` документа, поэтому не меняет Markdown, dirty-флаг, diff или snapshot. `Scaffold.bottomBar` резервирует formatting toolbar в edit-mode и компактную 48 dp панель `A− · N sp · A+` в read-mode; comparison dock располагается выше соответствующей панели.

Expanded formatting toolbar остаётся высотой 50 dp, но actions собраны в четыре pill-группы: text `H₁/B/I`, lists `•/1./☑`, insert `<>/🔗`, size `A−/A+`. Между группами 2 dp; collapse chevron вынесена отдельно. Modifier weight сохраняет все действия на одной строке без горизонтального scroll.

Header открытого документа состоит из top row 48 dp и mode selector 32 dp вместо первоначальных 58/42 dp. Back, Save и Export сохраняют 48 dp touch-targets. `TopBarTextAction` выравнивает glyph top `Сохранить/Экспорт` со строкой имени файла, а status остаётся второй строкой только в title-column. Уменьшение общей высоты достигается внутренними отступами и tabs, а не обрезанием действий.

List blocks в `MarkdownPreview` используют естественную ширину prefix вместо фиксированной 28 dp колонки. После bullet, number или checkbox добавляется отдельный spacer 8 dp; prefix line height равен body line height. Поэтому маленький `•` не создаёт пустой столбец, а `10.` и более длинные номера расширяются без clipping.

`MainActivity` работает edge-to-edge только с manifest-режимом `android:windowSoftInputMode="adjustResize"`. Это передаёт IME insets в Compose и не позволяет Android одновременно сдвигать всё окно через `adjustPan`. `EditorBody` применяет `WindowInsets.ime.exclude(WindowInsets.navigationBars)` и дополнительный bottom padding, равный измеренной высоте dock. Верх и ширина `BasicTextField` стабильны, нижняя граница всегда заканчивается выше toolbar/IME/dock. Размер активного viewport и вертикальный `ScrollState` доступны редактору напрямую. После resize caret rect сравнивается с видимыми границами; fallback прокручивает viewport только когда caret действительно вышел за них и не добавляет дополнительный safe margin. Если нативный `BasicTextField` уже завершил bring-into-view, target остаётся равен текущему scroll и второй анимации нет. Selection offset никогда не меняется ради прокрутки, поэтому caret handle не телепортируется между соседними символами.

`DocumentRepository` хранит множество UUID-проектов. Лёгкий `project_catalog` содержит IDs и активную карточку; имя, URI импортированного источника, последнее сохранение и текущий черновик находятся в отдельном приватном preferences-файле `project_<id>`. Запись черновика откладывается на 220 мс, поэтому набор текста не вызывает дисковую операцию для каждого символа. Неизменяемые сохранения изолированы в `filesDir/projects/<id>/versions`: каждый текст атомарно записывается в собственный UTF-8 GZIP-файл, а timestamp зашит в безопасный идентификатор. Работа с внешним `.md` проходит через Storage Access Framework; приложение сохраняет выданное системой разрешение и не требует общего доступа к накопителю.

Каждый проект хранит отдельный boolean `hasSavedBase`. Пустая строка не может заменить этот признак: она может означать и новый несохранённый проект, и существующий сохранённый пустой файл. Пока флаг false, `scheduleComparison` принимает текущий текст без вызова diff-движка и публикует пустые диапазоны. Успешный `markSaved` фиксирует флаг навсегда; импорт создаёт проект с флагом true. Старые установки выводят значение из URI, непустой базы или существующих снимков и затем сохраняют явно.

Домашний `LazyColumn` получает только `ProjectSummary`: ID, имя, dirty-флаг, число версий и время обновления. Полные тексты читаются только при открытии карточки. Создание и импорт генерируют новый UUID и уникализируют повторяющееся имя. Переименование не затрагивает внешний URI. Удаление очищает preferences и `projects/<id>` выбранного проекта; marker `catalog_initialized` не позволяет демо-проекту воскреснуть после удаления последней карточки.

При изменении текста ViewModel немедленно обновляет видимый черновик, сбрасывает устаревшую подсветку и через 70 мс запускает `AdaptiveDiffEngine` на `Dispatchers.Default`. Результат принимается только если оба исходных текста всё ещё актуальны. Это исключает мерцание неправильных диапазонов при быстром наборе.

## Обновления приложения

Self-update изолирован от редактора и project repository. `UpdateViewModel` владеет коротким UI-state machine, `GitHubReleaseUpdater` выполняет сетевую и криптографическую часть, а `UpdateInstaller` только передаёт уже проверенный файл системному Android installer.

Поток запускается исключительно действием пользователя:

1. `GET /repos/Krablante/textory/releases/latest` получает последний опубликованный stable release; draft и prerelease не участвуют.
2. Из assets выбирается production APK с HTTPS `browser_download_url`. Никакой GitHub token в приложении не хранится.
3. APK скачивается в `cacheDir/updates`, ограничен `100 MiB` и сверяется с размером и `sha256:` digest GitHub.
4. Android `PackageManager` подтверждает package `mom.cosmism.textory`, точное совпадение release tag и `versionName`, рост `versionCode` и SHA-256 production-сертификата.
5. `FileProvider` выдаёт installer одноразовый read URI. На Android 8+ пользователь при необходимости явно разрешает этому источнику установку APK.

Updater не имеет фонового worker, таймера, собственной базы, широкого storage-доступа или альтернативного канала обновлений. Частично загруженные и старые APK очищаются из приватного cache при следующей попытке.

## Адаптивное сравнение

Движок идёт от структурных единиц Markdown к видимым лексическим изменениям:

```text
документ
  └─ Markdown-блоки: абзацы, headings, list items, blockquotes, fenced code
       └─ уникальные Patience anchors
            └─ exact gaps: linear-space Myers
                 └─ переписанные блоки: монотонное similarity pairing
                      └─ Unicode word/whitespace/symbol tokens
                           └─ linear-space Myers + semantic cleanup
```

Уникальные нормализованные блоки формируют longest increasing sequence и не дают вставке в начале сдвинуть все последующие пары. В gaps библиотека `java-diff-utils 4.17` запускает Myers с linear-space backtracking. При равном числе переписанных блоков сохраняется позиционное pairing; при разном используется order-preserving Dice similarity, чтобы отделить вставку или удаление от соседней переписи. Идентичный блок, перенесённый через другой, остаётся добавлением плюс удалением: UI не скрывает изменение порядка под ложной заменой.

Внутри пары tokenizer сохраняет точные offset и различает слова, whitespace и symbol/emoji sequences, включая combining marks и ZWJ. Myers-регионы `insert + delete` нормализуются в замену. Cleanup объединяет соседние замены только через одинаковый whitespace, поэтому `быстро → медленно` и `небрежно → аккуратно` по разные стороны неизменного `и` остаются двумя диапазонами. Внешние пробелы, Markdown delimiters и стабильная punctuation не попадают в comparison. Полная перепись с одним технически общим знаком расширяется до целого блока.

Safety limits не допускают патологической работы: block Myers ограничен 4 000 units, token Myers — 8 000 units, similarity matrix — 40 000 cells. Для более крупного gap используется линейное prefix/suffix выравнивание; абзац свыше 500 000 суммарных символов сравнивается линейно по символам с расширением до границы слова. Golden-suite покрывает русский текст, Markdown, повторы, moves, Unicode/emoji, удаления, крупные документы, deterministic fuzz и точные UI offsets.

Дифф возвращает диапазоны только в текущем тексте. Замены нескольких соседних токенов объединяются вместе с пробелами между ними. Полное удаление имеет нулевой диапазон и отдельный `anchorOffset`; UI превращает его в боковой маркер, не меняя содержимое. Identity offset mapping режима правки и run-based raw-offset mapping режима чтения сохраняют связь подсветки с реальным Markdown. `ChangeHitResolver` централизует specificity, half-open границы и selection overlap; double-tap voting используется только дополнительным shortcut режима чтения.

Каждый успешный `markSaved` архивирует сохраняемый текст в папке активного project ID, затем делает его новой базой и удаляет diff. Для импортированного проекта запись в исходный URI через `ContentResolver` происходит до изменения состояния, но внутреннее переименование проекта сохраняется. Старый одиночный `editor_document`, `previousSavedText` и глобальный `document_versions` мигрируют в первую карточку при обновлении. Новый или импортированный документ получает отдельный пустой или начальный архив.

`VersionHistoryUiState` содержит только список идентификаторов/timestamp, выбранную позицию и небольшой lazy cache текстов. Тексты читаются на `Dispatchers.IO` по требованию; access-order cache ограничен четырьмя элементами, включая «Сейчас». `HorizontalPager` обеспечивает реальный свайп, а чипы дат программно перемещают тот же pager. Для выбранного historical snapshot экран вызывает тот же `AdaptiveDiffEngine(currentDraft, selectedSnapshot)` на `Dispatchers.Default`; результат всегда адресован показанному snapshot и не записывается в repository или ViewModel. UI-local `rememberSaveable` включает подсветку по умолчанию и позволяет скрыть её на всех страницах текущей viewer-сессии. Tap переиспользует `ComparisonDock` с контекстными label, временно заменяя нижнюю timeline. «Использовать эту версию» меняет только `currentText`, сохраняет базу и повторно запускает обычное сравнение. Экспорт использует отдельный `CreateDocument` и не меняет архив или URI проекта.

## Ограничения первой версии

Размер импортируемого файла ограничен 5 MiB, а распакованного исторического снимка — 10 миллионов символов, чтобы повреждённый файл не исчерпал память телефона. Формат предполагается UTF-8. Одновременно в редакторе активна одна карточка, но каталог и независимые архивы остальных проектов сохраняются. Снимки не синхронизируются и остаются только на устройстве. Настоящий release-signing не хранится в репозитории.
