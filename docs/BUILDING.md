# Сборка и проверка Textory

Проект использует Gradle Wrapper, JDK 17 и Android SDK с API 37. Команды выполняются из корня репозитория и не требуют нестандартной структуры каталогов.

## Основной quality gate

```bash
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Он запускает unit-тесты, Android Lint и собирает устанавливаемый debug APK:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Для установки на подключённое устройство:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Release-сборка

Без signing-переменных стандартные задачи создают оптимизированные неподписанные артефакты:

```bash
./gradlew assembleRelease bundleRelease
```

Для подписанной сборки задайте четыре переменные окружения:

```text
TEXTORY_RELEASE_STORE_FILE=/secure/path/textory-release.jks
TEXTORY_RELEASE_STORE_PASSWORD=...
TEXTORY_RELEASE_KEY_ALIAS=...
TEXTORY_RELEASE_KEY_PASSWORD=...
```

После этого `assembleRelease` и `bundleRelease` используют внешний ключ. Если задана только часть переменных, конфигурация завершается ошибкой вместо создания неоднозначного артефакта.

Ключ и пароли не должны находиться в репозитории. Храните их в защищённом secret storage и проверяйте итоговую подпись до публикации. Не распространяйте неподписанный или debug-подписанный APK как production release.

Открытый release-сертификат находится в `release/textory-release-cert.pem`. Его SHA-256 fingerprint:

```text
31:EB:C5:62:EE:DA:99:A8:74:6E:09:1B:DC:BF:68:08:19:AA:7C:02:E1:1D:AB:AE:63:15:BC:69:18:26:FB:78
```

Перед загрузкой APK сравните fingerprint командой `apksigner verify --print-certs <apk>`.

## Ручной smoke-check

Проверяйте итоговый release-артефакт на поддерживаемой версии Android после чистой установки и поверх предыдущей версии.

- Главный экран показывает компактный список, корректный счётчик и доступные действия создания и импорта.
- Создание и повторный импорт образуют независимые проекты; переименование и удаление не затрагивают соседние документы.
- Первый несохранённый черновик не получает ложный diff. После сохранения подсвечиваются только последующие изменения.
- «Сохранить» обновляет текущий проект, «Экспорт» создаёт отдельную копию и не меняет сохранённую базу.
- Режим чтения корректно отображает заголовки, списки, ссылки, цитаты и code; Select all охватывает документ целиком, а Copy содержит plain text и HTML.
- В режиме правки форматирование, нативное выделение, клавиатура и прокрутка курсора работают без скачков layout.
- Сравнение открывается только для выбранного изменения; навигация доходит до первого и последнего блока, а addition, deletion и replacement используют подходящий layout.
- Каждое сохранение добавляет версию. Старую версию можно просмотреть, скопировать и поместить в черновик без неявного сохранения.
- После перезапуска сохраняются документы, черновики, выбранный размер текста и архивы версий.
- `Проверить обновления` сообщает об актуальной версии либо предлагает только более новый production APK; отмена загрузки работает, неподходящие digest/package/version/signature отклоняются.
- Сеть используется только для ручной проверки GitHub Releases и скачивания подтверждённого APK. Широких storage-разрешений нет, backup остаётся отключённым.

Точные правила поведения находятся в [UX.md](UX.md), устройство данных и границы компонентов — в [ARCHITECTURE.md](ARCHITECTURE.md). Повторяемые вычислительные сценарии должны закрепляться unit-тестом, а не разрастаться в ручной checklist.

## Перед публикацией

- полный quality gate зелёный;
- version code и version name обновлены;
- release подписан production-ключом и проверен на чистой установке и обновлении;
- tag имеет вид `vX.Y.Z`, version name совпадает с ним, version code строго возрастает, а production APK загружен как `Textory-X.Y.Z.apk` с GitHub digest;
- `README.md`, notices и текст release notes соответствуют фактическому артефакту;
- репозиторий и его история проверены на секреты, signing-файлы, локальные пути и сгенерированные артефакты;
- у проекта есть явно выбранная лицензия в корне репозитория.
